# POR QUE ESTE ARQUIVO EXISTE
# O CI instalava o requirements.txt inteiro para rodar os testes. Isso arrastava
# dbt, prefect, streamlit e pysus -- nada disso e importado pela suite -- e a
# fragilidade cobrou: `dbt-core` puxou `dbt-core-experimental-parser 2.0.0b1`,
# um beta publicado sem wheel cuja metadata nao compila, e o job quebrou em
# Python 3.11 por um motivo sem nenhuma relacao com o codigo testado.
#
# A lista abaixo saiu de varredura por AST dos imports de tests/, validation/,
# ingestion/, ml/ e dos scripts que os testes importam. Ficaram de fora os
# imports LAZY (psycopg2 em validation/loader.py, datasus_dbc e dbfread em
# pipeline_sih_hospitalar.py), que so acontecem dentro de funcoes que a suite
# nao chama, e o prophet, cujos testes ja se marcam como skip quando falta.
#
# O QUE SE PERDE: o CI deixa de provar que requirements.txt instala. Esse teste
# tinha valor -- foi ele que revelou o conflito loguru x pysus -- mas ele estava
# preso ao job errado, derrubando os testes por causa da arvore de deploy.
#
# Versoes acompanham requirements.txt de proposito. O teto de loguru vem de la
# (pysus fixa <0.7.0): se a suite rodasse em 0.7 e a producao em 0.6, um teste
# poderia passar usando API que nao existe onde o codigo roda.
